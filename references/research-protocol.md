# 查證協定（research protocol）

本協定為 skill 自訂方法論（設計時定案），非外部已發表規則，故各條不附外部出處 URL。

## Contents
- 來源分級
- 四路搜尋
- 交叉驗證
- 「最新」保證機制
- research-digest.md 格式

## 來源分級

| 級別 | 定義 | 文章中可否引用 |
|---|---|---|
| L1 | 官方：docs、release notes、RFC、原始碼 | 可，優先 |
| L2 | 一手權威：框架核心成員、知名工程師第一手文章 | 可 |
| L3 | 優質二手：大型技術 blog、高品質社群文章 | 可，引用時標明屬社群觀點、非官方 |
| L4 | 論壇、未署名內容 | **不可引用**，只能當查證線索 |

中英文來源適用同一套分級——不因語言本身調高或調低級別，只看來源性質。

## 四路搜尋

深度查證階段派平行 subagent 分四路搜尋，每路鎖定不同性質的來源，彼此互補：

**官方文件／release notes／RFC／原始碼**
搜官方文件站、版本 release notes、RFC 文件、專案原始碼與 CHANGELOG。這一路產出的來源直接判為 L1，是文章中優先引用的依據。

**核心成員與權威作者的一手文章**
搜框架／工具核心維護者本人或知名工程師撰寫的第一手技術文章、conference talk、技術部落格（非官方帳號，但作者身份可核實）。判為 L2。

**中文社群優質文章**
搜中文技術社群中品質較高、內容具體可驗證的文章（例如技術部落格、鐵人賽系列文、社群平台上的深度分享）。多半判為 L3，引用時需標明是社群觀點、非官方說法；若追到源頭其實是轉譯或引用自官方文件或一手作者，改以原始出處判級。

**反方觀點與踩坑經驗**
搜踩坑紀錄、issue tracker 上的爭議討論、非官方視角的限制與批評，避免文章只呈現官方的樂觀敘事。這一路的判級要看發文者身份：具名工程師的踩坑文可能是 L2 或 L3；論壇貼文、未署名討論一律是 L4，只能當查證線索，不可直接引用。

## 交叉驗證

- 關鍵事實——版本號、API 行為、效能數字、棄用時程——至少要有**兩個獨立來源**佐證，才能寫進文章
- 來源之間有衝突時，以官方為準，並在 digest 中標記衝突點
- 官方文件內容過時、與較新的 release 不一致時，以較新者為準，並在文中寫明對應版本

## 「最新」保證機制

- 每個題目都必查該主題近期的 release／官方公告，用時間限定搜尋避免撈到過期資訊
- digest 記錄每個來源的**發布日期＋抓取日期**兩個時間點，兩者缺一不可
- 文章開頭標註「資訊基準日：YYYY-MM-DD，基於 <版本>」，讓讀者知道內容的時效範圍

## research-digest.md 格式

深度查證階段的產物，逐字採用以下格式：

```markdown
# Research Digest: <題目>
- 資訊基準日：YYYY-MM-DD
- 查證範圍：<搜尋的版本／時間範圍>

## 來源清單
| # | 級別 | 標題與 URL | 發布日 | 抓取日 | 要點 |
|---|---|---|---|---|---|

## 交叉驗證結論
（每條關鍵事實一行：主張 → 支持來源 #）

## 衝突與存疑
（來源互相矛盾處、只有單一來源的主張、標記「需查證」項）

## 時效警示
（哪些內容會隨版本過期、預期變動點）
```
